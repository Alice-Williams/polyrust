# M35-03A-02I-03A — Separate literal and constant value domains

- Status: complete

## Contract

Before extending LiteralValue, give compiler-evaluated scalar constants their
own closed ScalarConstantValue enum: Bool, I32 and I64. Scalar/local/public
declaration, read, import and export witnesses and both target mappings must
use that narrower domain end-to-end. No automatic conversion from a general
literal value is allowed. Compiler provenance and private witness construction
remain unchanged. This step changes no admitted Rust source or generated bytes.

## Definition of done and tests

- LiteralValue and ScalarConstantValue are distinct Rust types, not aliases.
- Backend-free positive probes type-check both domains and all existing
  constant witness accessors return the narrower enum.
- Two exact compiler-negative probes reject literal-to-constant and
  constant-to-literal assignment with E0308; neither can fail for missing
  dependencies, private fields or unrelated compilation errors.
- Existing C/Java constant compiler contracts, AST/provenance, native values,
  alias/original-owner and byte-determinism tests pass unchanged in strength.
- Full Linux Bazel release and Rust/Bazel-lint gates pass; an independent
  Sol Extra High review is clean before this checkpoint is committed/pushed.
- No f64 source, floating constants or runtime retirement is claimed.
