# M34A-10R — Java blind-review remediation

- Status: in-progress
- Depends on: M34A-10 implementation checkpoint
- Blocks: M34A-11

## Goal

Correct every Java core error found by independent review, prove the repaired
backend against adversarial checked programs and public Java consumers, and
repeat fresh blind review against pushed immutable commits until no core error
remains.

## Finding disposition

Accepted core findings:

1. Java must correctly lower checked `String` and Unicode-scalar `Char`
   ordering rather than emitting illegal relational operators.
2. Java identifier protection must cover every Java 21 reserved literal,
   keyword, restricted identifier, and the reserved single underscore.
3. Multiple interface conformances must either preserve distinct witnesses and
   Java-erased signatures or fail during shape-aware preflight with an
   attributed `UnsupportedShape` diagnostic; they must never reach invalid
   Java emission.
4. The Java plugin must own a typed, exhaustive, shape-aware capability
   registry which is invoked atomically by the public typed compiler before
   lowering.
5. Normal portable result propagation must use explicit tagged control flow,
   not private exception unwinding. The internal runtime inheritance exemption
   is removed.
6. Generated member/callable/constructor/field references must be checked
   against authoritative registrations, and the Java verifier must reject
   duplicate members, invalid scopes, invalid assignments, invalid returns,
   and incomplete concrete control flow before rendering.
7. Public option/result/bytes/character boundaries must prevent invalid
   portable states and mutable aliases.
8. Java-owned embedded templates must participate in the semantic template
   source-policy gate.
9. Native/public/negative/conformance evidence must exercise interface returns,
   overlapping-conformance policy, exact failure payloads, identifier
   protection, Unicode characters, and generated API type errors.

Partially accepted reviewability finding:

- Resolved identifier/type/expression fragments receive distinct private view
  wrappers as required by the rendering specification. Readable deterministic
  formatting is improved and frozen by generated-example snapshots. Adding an
  external Java formatter is not required: the Java specification makes a
  formatter optional, and `javac -Xlint:all -Werror` remains the semantic/lint
  authority.

## Definition of done

- Every accepted finding has a focused regression test which fails on the
  original checkpoint and passes on the repaired implementation.
- The Java capability registry is target-ID consistent, has no string strategy
  IDs or wildcard support fallback, and selection is consumed by lowering.
- No checked program can reach Java rendering with an unsupported Java shape.
- `Runtime.Halt`, `Runtime.capture`, `Runtime.unwrap`, internal exception
  heritage, and exception-based result propagation are absent.
- Public runtime values cannot construct contradictory tags, null payloads,
  invalid Unicode scalars, out-of-range bytes, or mutable aliases.
- Curated v0 and interface examples are materialized as reviewable deterministic
  snapshots under repository example policy and regenerated byte-for-byte in
  tests.
- Focused Java tests, every historical Java target, source/template policies,
  linters, uncached `//...`, and `//:release_gate` pass in the Linux container.
- The completed checkpoint is committed and pushed before every fresh blind
  review. Each review finding has an explicit accepted/rejected disposition;
  rejection includes a normative and technical rationale.
- A fresh Sol/xhigh blind reviewer reports no remaining core correctness or
  specification error.
- M34A-10V replaces Java's executable template path before the next blind
  review; that review includes the ADR-0005 certificate and renderer theorem.

## Tests

- Focused Rust unit tests for capability preflight, identifiers, target AST
  verification, runtime construction, lowering, and rendering.
- Hermetic Java 21 positive, public-consumer, conformance, and deliberate
  compile-fail targets for both canonical packages and adversarial fixtures.
- Deterministic snapshot regeneration checks for committed examples.
- `bazel test //crates/backend-java:all //crates/codegen:all //tools/policy:all
  --nocache_test_results --test_output=errors`.
- All historical Java generation/conformance/negative targets.
- Full repository and release gates required by M34A.

## Scope boundary

This task repairs violations of the accepted M34A architecture and Java
semantics. Optional language features, arbitrary Java-program generation,
source parsing, and unrelated renderer conveniences do not block completion.
