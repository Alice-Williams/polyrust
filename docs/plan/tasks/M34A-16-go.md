# M34A-16 — Migrate Go to typed generation

- Status: planned
- Depends on: M34A-15

## Goal

Generate idiomatic, fixed-semantics Go through a typed Go AST without embedding
or mutable public aliases.

## Definition of done

- Go owns all type, expression, precedence, statement/block/case, declaration,
  receiver, file/package, and template enums in its specification.
- Every CoreIR feature has an exhaustive Go strategy; exact admitted standard
  package types/functions have typed catalogue entries.
- Fixed-width arithmetic, exact F64 bits, Unicode, tagged values, immutable
  byte/list wrappers, failure flow, initialization, and evaluation order are
  verifier checked without `unsafe`, reflection, or panic/recover semantics.
- Flat interfaces, multiple conformance assertions, first-class/nested
  interface values, typed-nil exclusion, dynamic dispatch, and named-field
  delegation pass with no anonymous embedding or promoted methods.
- Imports/aliases, package initialization, helpers, files, tests, and module
  metadata are resolver-derived.
- Runtime declarations are Go AST; strict templates render resolved views and
  gofmt is a no-diff check.
- Raw Go/body/runtime constants, manual imports/helpers, and the legacy Go
  pipeline are deleted.
- The Go compliance row moves to **Pass** with exact evidence.

## Tests

- `bazel test //crates/backend-go:all --nocache_test_results --test_output=errors`
- Go AST/verifier/catalogue/import/helper/package/template matrices.
- Pinned gofmt no-diff, `go vet`, `go test ./...`, external consumer,
  negative fixtures, interface/typed-nil/aliasing corpus, and three-generation
  determinism.
- All M17-M33 Go historical port targets.

## Commit gate

Commit and push `M34A-16: migrate Go to typed AST` only when all Go and shared
typed-generation gates pass in the dev container.
