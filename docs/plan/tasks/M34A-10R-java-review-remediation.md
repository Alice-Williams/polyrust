# M34A-10R — Java blind-review remediation

- Status: in-progress
- Depends on: M34A-10 implementation checkpoint
- Blocks: M34A-11

## Goal

Correct every Java core error found by independent review, prove the repaired
backend against adversarial checked programs and public Java consumers, and
repeat fresh blind review against pushed immutable commits until no core error
remains.

## Finding disposition

Accepted core findings:

1. Java must correctly lower checked `String` and Unicode-scalar `Char`
   ordering rather than emitting illegal relational operators.
2. Java identifier protection must cover every Java 21 reserved literal,
   keyword, restricted identifier, and the reserved single underscore.
3. Multiple interface conformances must either preserve distinct witnesses and
   Java-erased signatures or fail during shape-aware preflight with an
   attributed `UnsupportedShape` diagnostic; they must never reach invalid
   Java emission.
4. The Java plugin must own a typed, exhaustive, shape-aware capability
   registry which is invoked atomically by the public typed compiler before
   lowering.
5. Normal portable result propagation must use explicit tagged control flow,
   not private exception unwinding. The internal runtime inheritance exemption
   is removed.
6. Generated member/callable/constructor/field references must be checked
   against authoritative registrations, and the Java verifier must reject
   duplicate members, invalid scopes, invalid assignments, invalid returns,
   and incomplete concrete control flow before rendering.
7. Public option/result/bytes/character boundaries must prevent invalid
   portable states and mutable aliases.
8. Java-owned embedded templates must participate in the semantic template
   source-policy gate.
9. Native/public/negative/conformance evidence must exercise interface returns,
   overlapping-conformance policy, exact failure payloads, identifier
   protection, Unicode characters, and generated API type errors.

Partially accepted reviewability finding:

- Resolved identifier/type/expression fragments receive distinct private view
  wrappers as required by the rendering specification. Readable deterministic
  formatting is improved and frozen by generated-example snapshots. Adding an
  external Java formatter is not required: the Java specification makes a
  formatter optional, and `javac -Xlint:all -Werror` remains the semantic/lint
  authority.

## Definition of done

- Every accepted finding has a focused regression test which fails on the
  original checkpoint and passes on the repaired implementation.
- The Java capability registry is target-ID consistent, has no string strategy
  IDs or wildcard support fallback, and selection is consumed by lowering.
- No checked program can reach Java rendering with an unsupported Java shape.
- `Runtime.Halt`, `Runtime.capture`, `Runtime.unwrap`, internal exception
  heritage, and exception-based result propagation are absent.
- Public runtime values cannot construct contradictory tags, null payloads,
  invalid Unicode scalars, out-of-range bytes, or mutable aliases.
- Curated v0 and interface examples are materialized as reviewable deterministic
  snapshots under repository example policy and regenerated byte-for-byte in
  tests.
- Focused Java tests, every historical Java target, source/template policies,
  linters, uncached `//...`, and `//:release_gate` pass in the Linux container.
- The completed checkpoint is committed and pushed before every fresh blind
  review. Each review finding has an explicit accepted/rejected disposition;
  rejection includes a normative and technical rationale.
- A fresh Sol/xhigh blind reviewer reports no remaining core correctness or
  specification error.

## Tests

- Focused Rust unit tests for capability preflight, identifiers, target AST
  verification, runtime construction, lowering, and rendering.
- Hermetic Java 21 positive, public-consumer, conformance, and deliberate
  compile-fail targets for both canonical packages and adversarial fixtures.
- Deterministic snapshot regeneration checks for committed examples.
- `bazel test //crates/backend-java:all //crates/codegen:all //tools/policy:all
  --nocache_test_results --test_output=errors`.
- All historical Java generation/conformance/negative targets.
- Full repository and release gates required by M34A.

## Scope boundary

This task repairs violations of the accepted M34A architecture and Java
semantics. Optional language features, arbitrary Java-program generation,
source parsing, and unrelated renderer conveniences do not block completion.

## Review and gate record

- Blind review round 1: all nine core findings above were accepted and
  remediated. The suggestion to require an external Java formatter was rejected
  as an optional enhancement because the normative Java specification makes it
  optional; deterministic snapshots plus `javac -Werror -Xlint:all` remain the
  required formatting and compiler evidence.
- Remediation checkpoint gate: 288 of 288 tracked repository tests passed
  uncached in the Linux development container. The user-owned untracked
  `examples/real-world/stdlib-abs` package was excluded because its in-progress
  BUILD file names a missing `differential_test.sh`; it was not modified.
- The independent `//:release_gate` matrix passed 230 of 230 tests uncached
  from the same final tree.
- Fresh blind review round 2 at `e03a6334189bfd8ac1064d168235c1c76a4c8311`:
  eight core findings accepted. These cover recursive option/result equality,
  deep public-value normalization, immutable closed interface values,
  Java-specific member-shape preflight, nested constant intrinsics, actual
  enum-keyed strategy consumption and minimal helper roots, remaining verifier
  trust-boundary holes, and the normative `byte[]` representation for bytes.
- Optional external-adapter implementation is not promoted into scope. The
  unused and unresolved AST variant will be removed because the specification
  permits but does not require Java framework inheritance support.
- The report's literal `javac --release 21` follow-up is rejected as a core
  defect: Bazel's hermetic `-source 21 -target 21 --system <JDK-21-image>`
  invocation enforces the same source, bytecode, and Java 21 platform API
  boundary. It remains an evidence wording cleanup, not a semantic gap.
- Hosted CI for `e03a633` reproduced a previously latent cold-Cargo race:
  auto-discovered `generate_v0` examples from seven packages collided on one
  output path. Round 2 assigns unique Cargo example target names and proves the
  fix from a clean checkout.
- Round 2 remediation represents bytes as defensively copied `byte[]` and gives
  every tagged/generated value typed equality methods. `semanticEquals` keeps
  portable IEEE language equality (NaN unequal, signed zero equal), while
  `deepEquals` recursively compares raw F64 bits for conformance expectations.
  The AST has an explicit
  enum-valued fresh-array ownership transition; its positive and negative
  verifier fixtures prevent mutable arrays from escaping by an ordinary cast.
- Generated public parameter and record-component boundaries now perform
  recursive `CoreTypeId`-directed reconstruction for lists, options, and
  results. The separately compiled semantic-edge consumer mutates both inner
  and outer source lists and proves no alias survives; it also proves nested
  malformed UTF-16 is rejected. No erased cast or reflection is used.
- Portable Java interfaces are sealed with an exact typed permits set derived
  from checked implementations. A deliberate external implementation fails
  under hermetic Java 21 compilation, and an interface without a generated
  implementation stops during shape preflight.
- Capability selection is validated feature-for-feature, including support
  mode and enum-valued lowering strategy, before any symbols or files are
  registered. The native conformance file no longer injects unselected
  operations, and a minimal program proves optional helpers stay absent.
- The Java AST verifier now covers authoritative generated/local references,
  true Java erasure, checked exceptions, modifier contexts, foreach element
  types, and complete interface implementations. Focused negative fixtures
  exercise each rejected shape.
- The specified uncached Java/codegen/policy gate passed 28 of 28 targets after
  round 2 remediation. The regenerated v0 and interface snapshots passed their
  byte-for-byte comparison target.
- The complete tracked repository replay passed 291 of 291 targets uncached in
  the Linux development container, including Rustfmt, Clippy, Buildifier,
  source/template/dependency policy, every Java positive and compile-fail
  target, native compilers, sanitizers, and differential conformance. The
  user-owned untracked `examples/real-world/stdlib-abs` work remains excluded
  and untouched.
- The independently composed `//:release_gate` replay passed 230 of 230 targets
  uncached from the same final tree. Checkpoint commit/push and a fresh blind
  review remain pending.
